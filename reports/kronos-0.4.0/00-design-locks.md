# 设计约束

更新：2026-10-27

## 已确认边界

- 只改 benchmark 仓库与本目录，不修改 Kronos 主仓，不推送、提 PR 或发布。
- 负载工作分两次放行：主任务先明确允许构建/正确性/pilot，正式性能/profile另待主机空闲及正式测量信号。当前均未放行；候选只使用随后提供的修复后精确SHA与隔离Maven仓库。
- 不把旧 `cade57dbb` 制品作为最终候选。不得用 Maven Central/SNAPSHOT 静默替代候选。
- 不连接用户原有数据库、不使用 3306。正式实验仅使用 `/usr/local/mysql/bin/mysqld` 的独立 datadir、独立 socket、`127.0.0.1:13307`，专用数据库、专用账号与合成数据。
- 启动前先检查 13307 未占用；创建 datadir 时拒绝已存在且归属不明路径；停库只使用本次专属 PID/socket，禁止全局 kill。`--no-defaults` 避免读取用户 MySQL 配置。
- 私有凭据只从环境或 Git 外权限 600 文件读入；禁止凭据命令行参数、日志 URL、Git diff 全量配置输出或报告复制。
- 原配置备份保留在仓库外私有目录，文件权限600；不要提交。保留原有 server-side prepared statement 配置意图。

## 比较定义

- 每个查询操作 = 获取连接/会话、构建 ORM 查询、执行一次相同投影的主键查询、完全物化结果、关闭连接/会话；工厂/池初始化与数据生成在计时之外。
- 结果由 benchmark 返回或传入 Blackhole；不能继续通过 Unit 接口丢弃实体/Map/标量。
- 物理 SQL 不必字节级相同（别名与引号可不同），但表、投影列顺序/集合、谓词、绑定值和类型、限制条款、往返次数必须逐项核对。多一次 SELECT/生成键/类型转换必须披露。
- 第一层缓存不跨操作；禁用 ORM 二级/结果缓存；保留各 ORM 常规解析/元数据缓存并披露，避免仅禁用 Hibernate 查询计划缓存。
- 查询数据固定、确定性生成，初始化采用共同 JDBC，DDL 由固定 SQL 管理，不用任一参赛 ORM 帮其他框架建表。
- 每个适配器拥有初始化与关闭生命周期；池最终关闭；Kronos 全局状态限定在隔离 fork，不能在同一 JVM 并行配置多个 Kronos 适配器。
- 主试验单线程、单连接池配置；并发可选独立实验，不能默认用线程不安全 Session/共享游标。
- 单行写入与批量写入分开；生成主键与应用赋值主键分开。共同语义比较先做赋值主键、同列 INSERT、一次提交；原生批处理策略作为独立场景，披露物理 SQL 与生成键成本。
- 插入不得随计时循环无限增长。优先 SingleShotTime，每迭代一次已知规模写入，在迭代 setup 重置到固定起始状态。不要用 Invocation 级 TRUNCATE 将巨额维护成本藏在每次读写间。
